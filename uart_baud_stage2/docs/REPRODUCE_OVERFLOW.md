# 主动溢出与清空恢复复现步骤

已有 0003/0004 记录通过核对，不需要为了本次代码归档重测。以下步骤供之后复现用；它描述整理后的激励方式，本轮未重新在板上执行。

`pc/send_uart_baud.py` 的常规输入限制为 1 至 64 字节，所以单次 `--ramp` 不会填满 1024 条 FIFO。记录版 Notebook 的溢出断言格只检查状态，也不会产生发送刺激。

1. 使用当前运行面板，接收档位设为 115200；Windows 的 CH343 端口以实际设备管理器为准，本例是 COM5。
2. 停止发送，读取并导出需要保留的旧数据，点击“开始新记录”。下面发送完成之前，不点击“读取数据”。
3. 在装有 pySerial 的 Windows Python 中执行下方命令。它发送 1280 字节：`00..FF` 重复 4 次，再接 256 个 `A5`。这轮输入主动超过 FIFO 容量。

```bat
py -c "import serial; s=serial.Serial('COM5',115200,timeout=1,write_timeout=5); n=s.write(bytes(range(256))*4+bytes([0xA5])*256); s.flush(); s.close(); print('sent',n)"
```

4. 命令结束后点一次“读取数据”。单次读取 256 条，预期为有效 `00..FF`，观察到溢出，FIFO 剩余 768。导出本轮 CSV/JSON。
5. 本实验接着检查清空恢复：确认发送已停，点击“开始新记录”。这一步会主动清除剩余 768 条未读事件；不要把它们写成已逐字核验的数据。
6. 在 `uart_baud_stage2` 目录运行常规 64 字节命令，再读取与导出：

```bat
py pc/send_uart_baud.py --port COM5 --baud 115200 --ramp
```

预期为 64 条有效 `00..3F`、0 条停止位错误、FIFO 为 0、未观察到溢出。新导出的编号会自动递增，不一定与历史 0003/0004 相同。

本实验不测量精确拒收字节数，也不验证剩余 768 条内容；没有硬件接收时间戳或丢字节计数器。Windows 写入返回值是软件发送结果，不代替线路仪器测量。
